What stayed

All 345 official labels; timestamped strokes; seed 198173; an 80/10/10 original-level split; simple resume; held-out-test separation. Production keeps whole-file generation/MD5 checks; medium/small record partial-source evidence.

What went away

Approval CSVs/sign-offs, freeze gates, code/README fingerprints, source-level SQLite, automatic conflict re-downloads, duplicate selected copies, TOON formatting and drive restrictions.

dataset-summary.json records labels, counts, source information and data hashes. Export checks the data once. Editing documentation does not invalidate the dataset. A small plain ID list handles optional exclusions.

01-download.py

Read one raw line; clean and sample it

Each stroke contains matching x, y and millisecond-time arrays. The example has a roof, walls and door, an empty stroke and an exact duplicate point.

The empty stroke and duplicate (10,50,100) disappear. The later (10,50,180) remains as a pause. Nonzero starting time and recognized=false remain.
Production ranks IDs while scanning the complete source.


02-prepare.py
Deduplicate retained originals, then split
One temporary SQLite index holds identities, hashes and candidate byte offsets, rather than another JSON copy. Conflicting IDs/labels and cross-label identical trajectories are quarantined. Same-label exact duplicates keep a deterministic representative.

These are counts per class. Assume our house enters training; every one of its partial views remains training data. Its official class ID is 153.
Records are written directly into split JSONL shards. Parquet manifests store their byte offsets and metadata. Temporary indexes are removed; candidates remain available. No selected/staging-selected copies or approval files are needed.
If a class is short, the error gives an explicit command to download a larger reserve. Preparation never starts that transfer silently.


03-preview.py · optional
Inspect drawings only if useful
The command makes training-only contact sheets. There is no mandatory review, 345-row CSV or approve-all command. To omit an individual drawing, add its ID to excluded-ids.txt and prepare again.
The small offline example and explicit source probe live in separate nonproduction directories. They do not establish real-game accuracy.


04-export.py
One final check, then separate archives
Audit verifies counts, split separation, IDs/trajectories, byte offsets, metadata and data hashes. It does not inspect README or code-file fingerprints.
Trainer
Training and validation records/manifests, labels, summary, installable data tools and uv setup.
Held-out test
Separate test records/manifests for the validation owner. No test-derived QA images enter the trainer package.
The normal export calls audit exactly once. Standalone audit is optional, not another mandatory step. Historical ZIPs are not rebuilt automatically.


05-loader.py
This is where one drawing is read
from guesser_data import IndexedDrawings

with IndexedDrawings("prepared", "train") as drawings:
    sample = drawings.training_image(0, epoch=0)
    image = sample["image"]       # float32 [3,224,224], when usable
    target = sample["class_id"]   # separate label
The reader uses a Parquet row's byte offset to seek directly to the original. It then asks the image functions to cut, render and preprocess that drawing. It does not download it again or load the entire dataset.
Training requests use a seeded view: 20% complete, otherwise 10%-90% elapsed time. Evaluation reads one original and yields ten fixed stages, retaining blank/uncertain/unchanged outcomes.
Only the image enters ViT. The label is its training target; timestamps create partial views but are not direct neural input features. Batch assembly belongs to the model project.


06-images.py
Cut → render → preprocess
The house starts at 100 ms and finishes at 1,700 ms. At 50% elapsed time the inclusive cutoff is 100 + 0.5 × (1700 − 100) = 900 ms.
Visible shape → fit within 192 → pad to 224x224
Repeat as three channels → normalize (pixel/255 - 0.5) / 0.5
float32 [3,224,224]: black ≈ -1, white ≈ +1
Use the same method in a model's training and inference. Foreground can return uncertain for mixed borders; edges can lose faint strokes or double-outline thick ones. Neither method silently switches to the other.




Streaming reduces memory use; it does not remove every bottleneck
Network
Production reads the dated 181.43 GiB inventory; smaller profiles stop early.
CPU
JSON parsing, cleaning, hashing and requested image transforms take time. A gaming GPU does not perform these preparation steps.
Disk
Candidates, prepared records, temporary indexes and ZIPs use capacity and disk bandwidth. Full raw files need not remain stored.
RAM
Normally two bounded candidate samples, one class at preparation time and small reader caches. Large drawings, reserves and training buffers can still increase RAM.
Batch buffers are separate
Input values only: current batch plus two prefetched batches per worker. Excludes rendering buffers, caches and model/GPU tensors. These are illustrative future training settings.
Images are generated on demand
One float32 image is 602,112 bytes. A 64-image batch alone is 36.75 MiB. One stored image per selected original requires extra disk space.
Current code prepares 1,725,000 originals, not all 50 million for training. Full-source memory/throughput and model performance remain unmeasured.


Repository layout: data tools live in models/guesser/data/; the incoming evaluation/notebook scaffold moved to models/guesser/evaluation/. Training and the inference service remain future work. Data keeps Python 3.13/uv; evaluation keeps its separate Python 3.12 lock.
The earlier implementation used limited offline cases and import/path checks. This dataset-size update uses three small offline checks. No source download, complete pipeline run, notebook execution, model training, frontend checks or historical export rebuild is part of this update.
